# Задание 2. Конспект по BPMN 2.0

## Назначение BPMN

BPMN — это нотация для описания бизнес-процессов в виде понятных схем. Она нужна, чтобы разные участники проекта одинаково понимали, как выполняется процесс: где он начинается, какие задачи идут дальше, где есть выбор, ожидание или ошибка. BPMN отличается от обычной блок-схемы тем, что у каждого элемента есть своё значение. Поэтому такую диаграмму проще проверить и использовать при анализе работы организации.

## Таблица элементов нотации

| Элемент | Графическое описание | Семантическое значение | Пример применения |
|---|---|---|---|
| Start Event | Тонкий круг | Начало процесса | Клиент сделал заказ |
| End Event | Круг с толстой границей | Завершение процесса | Заказ выдан клиенту |
| Task | Скруглённый прямоугольник | Одно действие в процессе | Принять заказ |
| User Task | Задача, выполняемая человеком в системе | Действие сотрудника с ИТ-поддержкой | Провести оплату в кассе |
| Manual Task | Ручная задача | Действие без информационной системы | Передать стакан клиенту |
| Service Task | Автоматическая задача | Действие, выполняемое системой | Отправить уведомление |
| Gateway XOR | Ромб с X | Выбор только одной ветки | Оплата прошла или нет |
| Gateway AND | Ромб с плюсом | Параллельное выполнение всех веток | Готовить напиток и собирать упаковку |
| Intermediate Event | Круг с двойной границей | Событие внутри процесса | Ожидание ответа 3 дня |
| Sub-Process | Задача с плюсом внутри | Группа действий, вынесенная отдельно | Приготовить заказ |
| Sequence Flow | Сплошная стрелка | Последовательность действий внутри одного пула | От принятия заказа к оплате |
| Message Flow | Пунктирная стрелка | Обмен сообщениями между пулами | Клиент отправляет данные заказа компании |
| Lane | Горизонтальная или вертикальная дорожка | Роль внутри участника процесса | Кассир, бариста |
| Pool | Большой контейнер | Участник процесса или организация | Клиент, кофейня |
| Text Annotation | Поясняющий текст | Комментарий без влияния на выполнение | Уточнение условия оплаты |

## Типы шлюзов

| Шлюз | Когда применяется | Пример из практики | Типичная ошибка |
|---|---|---|---|
| XOR | Когда из нескольких вариантов выбирается только один | Оплата прошла / оплата не прошла | Не подписать условия на исходящих потоках |
| AND | Когда нужно запустить все ветки одновременно | Параллельно приготовить напиток и собрать упаковку | Использовать AND там, где реально нужен выбор |
| OR | Когда может выполниться одна или несколько веток | Клиент может выбрать доставку, упаковку и бонус | Путать OR с XOR |

## Типы подпроцессов

Collapsed Sub-Process — это свёрнутый подпроцесс. На основной диаграмме он выглядит как одна задача с плюсом, а подробности раскрываются на отдельной схеме. Такой вариант удобно применять, когда основной процесс не нужно перегружать деталями.

Expanded Sub-Process — это раскрытый подпроцесс. Его шаги видны прямо внутри основной диаграммы. Такой вариант удобен, когда деталей немного и важно видеть их сразу.

В своей итоговой BPMN-модели я использую Collapsed Sub-Process, потому что приготовление заказа в кофейне состоит из нескольких действий, но на основной схеме лучше оставить общий порядок процесса.

## Чек-лист проверки BPMN-диаграммы

1. У процесса есть понятное начальное событие.
2. У каждой завершающей ветки есть конечное событие.
3. Названия задач записаны глаголами: «Принять заказ», «Проверить оплату».
4. У шлюза XOR подписаны условия на исходящих потоках.
5. Sequence Flow не пересекает границу пула.
6. Message Flow используется только между разными пулами.
7. Дорожки соответствуют реальным ролям участников.
8. Подпроцесс имеет отдельную раскрытую схему.
9. На диаграмме нет стрелок, которые «висят» без начала или конца.
10. Схема не перегружена мелкими действиями, которые можно вынести в подпроцесс.
